PERF-002 benchmark evidence

Implementation:
  SessionSummaries uses correlated COUNT/MAX/last-payload subqueries keyed by
  chat_sessions.id. It does not join message rows to thread rows, so the
  aggregate remains one SQL statement without a message/thread cross-product.
  The list route still uses exactly two statements: one summary read and one
  membership read, with zero chat_deliveries queries.

Commands:
  go test -run '^$' -bench 'BenchmarkSessionList$' -benchtime=20x -count=1 ./internal/session/
  go test -run '^$' -bench 'BenchmarkSessionList' -benchtime=20x -count=1 ./internal/session/

The first command is the shipped 20-session instrument. The second command runs
that benchmark and the separate BenchmarkSessionList200 scale benchmark. Both
fixtures use 20 messages per session and 20 timed requests after warm-up.

Measured after de-fanning:
  20 sessions x 20 messages: p50 0.440 ms, p95 0.552 ms
  200 sessions x 20 messages: p50 3.532 ms, p95 4.413 ms
  benchmark loadavg: 2.22 2.41 2.31 (20-session run); 2.97 2.54 2.35
    (combined 20-session plus 200-session run)

Acceptance:
  p50 <= 5 ms @ 20x20: MET (0.440 ms)
  p50 <= 20 ms @ 200 sessions: MET (3.532 ms)

Before this change, the merged aggregate measured p50 12.06 ms / p95 12.71 ms
at 20x20 and p50 141.89 ms / p95 148.15 ms at 200x20. The prior 100 ms
project benchmark budget is not used as either PERF-002 acceptance bound.
