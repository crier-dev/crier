## 2. Signed round trip (`CR_REQUIRE_AGENT_SIG=true`)

`"<METHOD>\n<path>\n<unix-seconds>"`, with a 4th line `sha256:<hex>` for a body-bound
request and a 5th `audience:<value>` when `X-Crier-Audience` is set
(`docs/service-delivery-auth.md:31`). Keys: `crier keygen` (PKCS#8 PEM ed25519).

### 2.3 The unsigned send on the ordinary path is **ACCEPTED** — measured, not assumed

```
--- 2. UNSIGNED deliver to agent-a (no signature trio at all) ---
{"id":"564138ae9fc59f0a35e000bf","transport":"inbox","expires_at":"2026-11-17T07:47:11.228375035Z", ...}
```

`HandleDeliver` → `deliver()` has no sender-signature gate (`internal/registry/handler.go:1122`);
`sender` is recorded as delivered. `CR_REQUIRE_AGENT_SIG` protects agent-scoped **reads/acks**
and (below) protected recipients — not the ordinary inbox delivery's sender claim. This is
the one place the brief's expectation ("an unsigned send is refused") does not hold on the
default delivery path; it is filed as next-wave row R-1 rather than papered over.
