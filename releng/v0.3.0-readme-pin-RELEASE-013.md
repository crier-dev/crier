## Criterion 4 — the drift lock: OPTION A (documented cut-time step)

Chosen: a numbered cut-time step in `docs/releases.md` §1 ("Write the changelog
entry first"), inserted as step 4 with the existing commit step renumbered to 5.

Rejected: an assertion in `make docs-check` that the README pin equals the
newest tag. Reasons, recorded in the step itself so the next releng reader sees
them:

- the CI checkout is shallow and fetches no tags, so "README pin == newest tag"
  either passes vacuously (no tags -> nothing compared) or fails every run on a
  host that has not fetched tags — a gate that is vacuous where it matters is
  worse than a named process step;
- `make docs-check` is `go test -run TestDocsClaims ./cmd/server`, whose claims
  are (id, doc, quote, expectation) records over prose and live probes; a claim
  anchored on the version string would have to be edited in the same commit that
  moves the string, i.e. it would add a second hand-maintained copy rather than
  a lock.

The step moves all three README mentions together with the changelog entry in
ONE commit, so the tag point can never contain a changelog entry without the
matching pin.
